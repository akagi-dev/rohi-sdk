Set fields of a section: `FIELD=VALUE` pairs, stored atomically.

Fields that are not mentioned keep their value; a section that is not configured yet starts from its defaults, and the complete result is validated by the device. Secret fields are never given on the command line: use `FIELD=-` to read the value from stdin, or to be asked for it on a terminal. Bytes are given as hex.

Usage: rohi config set [OPTIONS] <SECTION> <FIELD=VALUE>...

Arguments:
  <SECTION>
          The section

  <FIELD=VALUE>...
          `FIELD=VALUE` pairs

Options:
      --dry-run
          Validate on the device without storing anything

  -h, --help
          Print help (see a summary with '-h')

Target:
  -d, --device <DEVICE>
          Target device: advertised name, ID, or a unique prefix or suffix of either; or a URI such as ble://NAME or tcp://HOST:PORT. Without it the only device found is used, or you choose among several
          
          [env: ROHI_DEVICE=]

Output:
  -o, --output <FORMAT>
          Output format

          Possible values:
          - human: Text for people
          - json:  JSON with a stable, versioned schema, for scripts
          
          [default: human]

      --color <WHEN>
          Color the text output

          Possible values:
          - auto:   Color when stdout is a terminal, unless `NO_COLOR` is set or `TERM` is `dumb`
          - always: Always color
          - never:  Never color
          
          [default: auto]

Connection:
      --scan-timeout <SECONDS>
          How long to search for the target device
          
          [default: 10]

      --timeout <SECONDS>
          How long to wait for a device response
          
          [default: 10]

Examples:
  rohi config set connectivity host=ingress.example.org port=443 enabled=true
  rohi config set connectivity interval_s=120 --dry-run
  rohi config set network ssid=office password=-
  echo 'hunter2hunter2' | rohi config set network password=-
