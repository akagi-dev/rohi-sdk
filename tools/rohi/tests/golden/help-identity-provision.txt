Derive an identity from a master seed and install it.

The master seed stays on this machine; the device receives only the secret derived with the hard junction `//<NUMBER>`. Use every number once per master: the device cannot detect duplicates.

Usage: rohi identity provision [OPTIONS] --number <NUMBER> --seed <FILE>

Options:
  -n, --number <NUMBER>
          Sensor number used for the hard derivation `//<NUMBER>`

      --seed <FILE>
          File with the master secret URI (mnemonic phrase or `0x` seed, optional path); it is read here and never sent to the device

  -h, --help
          Print help (see a summary with '-h')

Target:
  -d, --device <DEVICE>
          Target device: advertised name, ID, or a unique prefix or suffix of either; or a URI such as ble://NAME or tcp://HOST:PORT. Without it the only device found is used, or you choose among several
          
          [env: ROHI_DEVICE=]

Output:
  -o, --output <FORMAT>
          Output format

          Possible values:
          - human: Text for people
          - json:  JSON with a stable, versioned schema, for scripts
          
          [default: human]

Connection:
      --scan-timeout <SECONDS>
          How long to search for the target device
          
          [default: 10]

      --timeout <SECONDS>
          How long to wait for a device response
          
          [default: 10]

Examples:
  rohi identity provision --number 42 --seed master.suri
  rohi id provision -n 42 --seed master.suri
