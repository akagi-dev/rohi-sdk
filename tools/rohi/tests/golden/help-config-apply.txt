Apply a configuration file.

A field that is missing in the file is left unchanged, a field set to `null` is unset, and a section set to `null` is reset. Every section is validated on the device before the first one is changed, and each section is applied atomically. Applying several sections is not atomic as a whole: if the device fails in between, the sections already applied are listed.

Usage: rohi config apply [OPTIONS] <FILE>

Arguments:
  <FILE>
          The JSON file; `-` reads stdin

Options:
      --dry-run
          Validate on the device without storing anything

  -y, --yes
          Skip the confirmation prompt

  -h, --help
          Print help (see a summary with '-h')

Target:
  -d, --device <DEVICE>
          Target device: advertised name, ID, or a unique prefix or suffix of either; or a URI such as ble://NAME or tcp://HOST:PORT. Without it the only device found is used, or you choose among several
          
          [env: ROHI_DEVICE=]

Output:
  -o, --output <FORMAT>
          Output format

          Possible values:
          - human: Text for people
          - json:  JSON with a stable, versioned schema, for scripts
          
          [default: human]

      --color <WHEN>
          Color the text output

          Possible values:
          - auto:   Color when stdout is a terminal, unless `NO_COLOR` is set or `TERM` is `dumb`
          - always: Always color
          - never:  Never color
          
          [default: auto]

Connection:
      --scan-timeout <SECONDS>
          How long to search for the target device
          
          [default: 10]

      --timeout <SECONDS>
          How long to wait for a device response
          
          [default: 10]

Examples:
  rohi config apply config.json --dry-run
  rohi config apply config.json
  rohi config apply config.json --yes
