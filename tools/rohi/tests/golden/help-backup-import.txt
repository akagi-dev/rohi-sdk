Validate and restore device configuration.

The whole backup is validated, and compared with the device, before anything is changed. A backup that is malformed, has an unsupported schema version, or holds sections the device cannot restore is rejected without changes. Secrets missing from the backup are asked for. The restore is not atomic: if a section fails, the ones already applied are reported.

Usage: rohi backup import [OPTIONS] <FILE>

Arguments:
  <FILE>
          Backup file written by `rohi backup export`

Options:
      --dry-run
          Show the planned changes without modifying the device

  -y, --yes
          Skip the confirmation prompt

      --wifi-password-stdin
          Read the Wi-Fi password from the first line of stdin, if the backup requires one. ROHI_WIFI_PASSWORD works too

  -h, --help
          Print help (see a summary with '-h')

Target:
  -d, --device <DEVICE>
          Target device: advertised name, ID, or a unique prefix or suffix of either; or a URI such as ble://NAME or tcp://HOST:PORT. Without it the only device found is used, or you choose among several
          
          [env: ROHI_DEVICE=]

Output:
  -o, --output <FORMAT>
          Output format

          Possible values:
          - human: Text for people
          - json:  JSON with a stable, versioned schema, for scripts
          
          [default: human]

Connection:
      --scan-timeout <SECONDS>
          How long to search for the target device
          
          [default: 10]

      --timeout <SECONDS>
          How long to wait for a device response
          
          [default: 10]

Examples:
  rohi backup import backup.json --dry-run
  rohi backup import backup.json
  rohi backup import backup.json --yes --wifi-password-stdin
